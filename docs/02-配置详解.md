# 02 · 配置详解

所有配置都在 **AstrBot 面板 → 插件 → QQ空间 → 配置** 里，不用改代码。
标注 🆕 的是本 Fork 新增项。

---

## 根级配置

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `manage_group` | string | 空 | 表白墙稿件的审批群号。**留空**则审批信息私发给管理员 |
| 🆕 `qzone_cookie` | text | 空 | 手工 QQ空间 Cookie（含 `p_skey`、`uin`）。**填了它就优先使用，服务器无需登录 QQ**；留空则回落到 NapCat 的 `get_cookies` |
| 🆕 `qzone_cookie_file` | string | 空 | Cookie 文件路径，**优先级最高**。配合 [`keeper/`](../keeper/README.md) 保活服务使用：服务会定时把最新 Cookie 原子写入该文件，插件自动跟上，**无需重启 AstrBot** |
| `cookie_ttl` | int | `600` | Cookie 缓存刷新间隔（秒）。到点会重新读取一次 Cookie（**决定插件多久跟上文件里的新 Cookie**） |
| `timeout` | int | `10` | HTTP 请求超时（秒）。网络差可调大到 20 |
| `show_name` | bool | `true` | 卡片里是否显示昵称 |

**Cookie 三个来源的优先级**：

```
qzone_cookie_file（文件，若文件存在且有内容）
        ↓ 否则
qzone_cookie（面板里手填的）
        ↓ 否则
NapCat 的 get_cookies（需要 QQ 客户端在线）
```

> 文件路径要用**容器内路径**：`/AstrBot/data/plugin_data/astrbot_plugin_qzone/qzone_cookie.txt`
> 非 Docker 部署则是相对于 AstrBot 根目录的 `data/plugin_data/...`。

## `llm` — LLM 模块

只在「评论说说 / AI 写说说 / 回复评论」时用到。**纯点赞模式不需要配置任何 LLM。**

| 配置项 | 说明 |

| `post_prompt` | 写说说的提示词 |
| `comment_provider_id` | 评论说说用的 LLM 提供商 |
| `comment_prompt` | 评论的提示词 |
| `reply_provider_id` | 回复评论用的 LLM 提供商 |
| `reply_prompt` | 回复评论的提示词 |

## `trigger` — 触发配置（重点）

| 配置项 | 类型 | 默认 | 说明 |
|---|---|---|---|
| 🆕 `like_only` | bool | `true` | **只点赞不评论**。开启后 `AutoComment` 任务整体跳过，点赞交给 `AutoLike`。想恢复上游行为设为 `false`（会挨个评论好友动态，且评论失败会连带跳过点赞） |
| 🆕 `like_cron` | string | `0 */2 * * *` | 自动点赞的**基准时间**（Cron：分 时 日 月 周）。**留空 = 关闭自动点赞** |
| 🆕 `like_offset` | int | `900` | 围绕基准时间随机前后浮动的秒数。`0` = 严格按点触发（不推荐，时间特征明显） |
| 🆕 `like_num` | int | `20` | 每轮最多处理动态流最新 N 条 |
| 🆕 `like_delay_min` | int | `8` | 每条点赞之间的最小间隔（秒） |
| 🆕 `like_delay_max` | int | `20` | 每条点赞之间的最大间隔（秒） |
| 🆕 `like_use_http_key` | bool | **`true`** | 点赞接口的 `unikey`/`curkey` 用 `http://` 拼接。**实测必须开启**：用 `https://` 时接口照样返回 `succ`，但服务端直接忽略，赞根本点不上。详见 [03 · 根因报告](03-点赞失效根因报告.md) |
| `publish_cron` | string | `30 23 * * *` | 自动发说说的基准时间，**留空 = 关闭** |
| `publish_offset` | int | `600` | 自动发说说的时间浮动（秒） |
| `comment_cron` | string | `0 8 * * *` | 自动评论好友动态的基准时间，**留空 = 关闭**。纯点赞模式下建议留空 |
| `comment_offset` | int | `600` | 自动评论的时间浮动（秒） |
| `like_when_comment` | bool | `true` | 评说说时顺便点赞（只在 `like_only=false` 时有意义） |
| `read_prob` | float | `0.001` | 群聊 / 私聊时随机触发「读说说」的概率。建议保持极小 |
| `send_admin` | bool | `false` | 触发读说说时只私发给管理员，不发到群里 |

### 定时语义：基准时间 + 随机偏移

```
*_cron      = 基准时间点（Cron 表达式）
*_offset    = 围绕基准点随机浮动的秒数（±N）
实际执行时间 = 基准点 ± N 秒内随机
```

**例**：`like_cron = 0 */2 * * *` + `like_offset = 900`
→ 每两小时一次；执行时刻落在基准点前后 15 分钟内的随机一点（如 02:00 的这轮可能在 01:47~02:15 之间触发）。

**为什么这么设计**：避免"每次都在整点发请求"这种明显的机器特征。

### 推荐参数组合

| 场景 | like_cron | like_offset | like_num | 延时 |
|---|---|---|---|---|
| **保守**（推荐，够用且风险低） | `0 */2 * * *` | `900` | `20` | 8~20 秒 |
| 更保守（一天 4 次） | `0 */6 * * *` | `1800` | `20` | 10~30 秒 |
| 活跃（每半小时） | `*/30 * * * *` | `300` | `10` | 15~40 秒 |

> ⚠️ 不建议把间隔压到几分钟以内。QZone 对高频写操作是有风控的，点赞这种事也不需要那么快。

## 关于去重（`liked_tids.json`）

`AutoLike` 任务会把**已成功点赞**的动态 `tid` 记录到插件数据目录：

```
<AstrBot data>/plugin_data/astrbot_plugin_qzone/liked_tids.json
```

- 只保留最近 2000 条，超出自动截断
- 每轮开始会跳过已记录的 `tid`，**不会重复点赞同一条动态**
- 想让它重新点一遍（比如换了账号、或之前是假成功），**删掉这个文件**即可
